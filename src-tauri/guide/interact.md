**Interact:**
- `click --x X --y Y` | `click --selector CSS` | `click --text "..."` — click by coordinates, selector, or text
- `hover --selector CSS` / `hover --x X --y Y` — move the cursor (macOS uses native CGEvent so CSS `:hover` fires; Windows/Linux dispatch JS events only and set `native_hover: false`; the Chrome engine moves Chrome's own pointer, `native_hover: true`). Use this for dropdown menus and tooltips.
- `fill-form --selector CSS --value TEXT` — fill single field (shorthand)
- `fill-form --fields '[{"selector":"#a","value":"1"}]'` — fill multiple fields (JSON)
- `keyboard --text "hello"` | `keyboard --text "long" --paste` — type or paste text
- `keyboard --key Enter [--modifiers ctrl,shift]` — press special keys
- `keyboard --key Tab --native` — a native key press the page receives with `isTrusted: true` (the plain one is a JS event, `false`): an NSEvent on macOS, CDP `Input.dispatchKeyEvent` on Windows WebView2; not on Linux. Focus crosses into cross-origin iframes and closed shadow roots. No Accessibility permission; the mouse does not move. Named keys only, not `--text`. A Cloudflare Turnstile checkbox: `--key Tab --native`, then `--key Space --native`. The Chrome engine's keys are always trusted.
- `scroll --to top|bottom|left-end|right-end [--selector CSS]` — absolute scroll
- `scroll [--direction down] [--amount 500] [--selector CSS]` — relative scroll. It scrolls what a **mouse wheel** would: the window, or the page's inner scroller when the window cannot scroll (a docs site whose text scrolls inside `#page`). The result is measured: `moved`, `scrolled` (the real distance; `requested` is what you asked), `container`, `at_start`/`at_end`. When nothing moved it says why and lists `scrollables`. `--selector` always wins.
- `upload-file --selector "input[type=file]" --file PATH`
- `save-image --selector CSS --output PATH [--index -1]` — save DOM image (default: last match)
